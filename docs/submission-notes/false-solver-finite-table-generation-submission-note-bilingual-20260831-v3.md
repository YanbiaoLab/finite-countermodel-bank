Submission note: self-unpacking solver code; offline generation and selection of the False Solver’s 1,487 embedded finite-magma tables.

A Python launcher decodes the Base85/LZMA solver bundle in memory.

Contents. The submitted payload embeds 1,487 exact operation tables: a 1,470-table positive-marginal core selected from 3,535 candidates, plus 17 finite149 records. Each record is one carrier-order byte followed by n^2 row-major entries; the stream is LZMA-compressed and Base85-encoded.

Offline discovery of the core. The core is the compact result of an offline model-mining campaign run from May 2026 onward, not answers generated during evaluation. The input universe was the Equational Theories Project list of 62,576 order-at-most-5 equations together with evolving unresolved directed source/target pairs from development and hard-case sets.

Codex was used offline to inspect reports, propose searches, revise scripts, and analyze bounded runs; its output was never mathematical evidence. Automated theorem provers supported discovery, while finite-model and SAT/SMT backends produced explicit tables. Tools included ETP finite refutations, small-magma enumeration, Python generators, CaDiCaL/PySAT, and bounded Mace4, Z3, and cvc5. Timeouts, UNKNOWN, and fixed-order UNSAT were not verdicts.

Candidate families included affine and linear operations, Boolean and F2^3 completions, products, lifts, isotopes, semidirect and wreath constructions, cocycles, feedback, mutations, and repairs. Historical mining produced 229,666 model identities. Evaluation on all 62,576 equations computed S(M), the laws a model satisfies, and R(M), the laws it refutes, covering S(M) x R(M). First-witness attribution left 9,452 nonzero contributors, of which 9,450 tables were recoverable.

Bank assembly. The 9,450 recoverable primary tables were disjoint from 402 registered tables, giving 9,852. Adding 66 early d1 tables contributed 11 new tables after 55 overlaps; adding 145 d2 tables contributed 94 after 51 overlaps. This gave 9,957 distinct tables. A later delivery added 102 independently verified tables with no exact overlap, producing the accumulated bank of 10,059.

Core selection. We removed 241 scalar-affine tables regenerated by the solver's affine enumerator and 6,283 tables of order at most 4 regenerated by Fin4/CDCL search, leaving 3,535 order-greater-than-4 candidates. The later delivery contained one order-4 table, so 101 of its 102 tables remained in this candidate pool. Only explicit tables passing independent exhaustive checks were retained.

The targeted false-pair universe contained approximately 324 million directed pairs. Fin4 independently covered approximately 40 million, leaving approximately 284 million residual pairs. Recomputing the 3,535 candidates' coverage on that residual removed 2,065 zero-marginal candidates and retained the 1,470 tables that each added coverage beyond Fin4.

finite149 augmentation. A later audit began from 789 directions for which an order-4 experiment generated no submission. Exactly 149 had an official false label and a finite outcome ending in proof_false. The ETP finite implication graph located proved model paths for all 149, and the referenced tables were extracted from Lean sources. The graph only located candidates; each table was then checked directly: the source had to hold under every assignment and the target had to fail under a concrete assignment.

The 149 directions reduced to 17 exact official base tables. Eleven also required the opposite orientation, giving 28 task-specific oriented tables: 17 originals and 11 strict transposes. Of the 149 directions, 129 used an original and 20 used a transpose. None of these assets occurred in the previous 1,470-table library.

Exact payload integration. The 17 appended records are 16 byte-exact official tables plus one verified substitute. For Refutation934, an order-22 closed substructure replaces the order-24 official table because its historical flat-table Lean certificate exceeded the verification limit. The order-22 table was exhaustively verified on the same five tasks. The payload therefore does not embed the order-24 table.

Generic opposite closure. At runtime the solver generates the strict transpose of every embedded table whose transpose is absent. This generic table transformation adds 1,414 distinct transposes to the 1,487 embedded records, producing a 2,901-table oriented runtime scan. These are runtime-derived models, not extra payload records or problem-ID branches.

Validation and proof boundary. Decoding checks order, length, and entry range; exact row-major deduplication does not merge isomorphic byte-distinct tables. Coverage data, graph paths, and rankings guide selection, never proof. At runtime a table is used only after rechecking the source and finding a target counterassignment. The certificate must pass the official Lean judge.

Python 启动器在内存中解码 Base85/LZMA solver bundle。

数据内容。本次提交载荷包含 1,487 张精确方形运算表：前 1,470 张是从 3,535 张候选表中筛选出的正边际核心库，随后 17 条记录来自 finite149 更新。每条记录由一个表示载体阶数 n 的字节及随后按行优先排列的 n^2 个表项组成；拼接后的数据流经过 LZMA 压缩和 Base85 编码。

核心库的离线发现。这些表是从 2026 年 5 月开始持续进行的离线模型挖掘（offline model mining）的紧凑结果，并不是正式评测时针对输入临时生成的答案。输入空间包括 Equational Theories Project 的 62,576 条至多 5 阶方程，以及从开发集和困难题集中持续更新的未解决有向源方程/目标方程问题对。

Codex 在离线阶段作为研究和编码智能体参与：读取剩余集合及覆盖报告，提出模型族和搜索方向，修改实验脚本并分析有界实验。Codex 输出从不直接作为数学证据。自动定理证明器用于发现和分流，有限模型查找器及 SAT/SMT 后端负责产生显式候选表。工具组合包括 ETP 有限反驳、低阶原群穷举、Python 生成器、通过 PySAT cadical195 调用的 CaDiCaL 1.9.5，以及有界的 Mace4、Z3 和 cvc5。超时、UNKNOWN 和固定阶数 UNSAT 从不被解释为蕴含结论。

候选模型族包括有限环和有限向量空间上的仿射/线性运算、Boolean 与 F2^3 完备化、直积、提升、同位变换、半直积与花环构造、上循环和反馈构造，以及对已验证表的变异和修复。历史挖掘产生 229,666 个模型身份。对全部 62,576 条方程穷举求值得到模型满足的 S(M) 和反驳的 R(M)，从而覆盖 S(M)×R(M)。首见证归属后有 9,452 个模型具有非零贡献，其中 9,450 张运算表可以恢复。

表库合并。9,450 张可恢复 primary 表与 402 张 registry 注册表没有精确重复，合并为 9,852 张。随后加入早期 d1 的 66 张表，其中 55 张重复，净增 11 张；加入 d2 的 145 张表，其中 51 张重复，净增 94 张，累计得到 9,957 张。后续交付的 102 张独立验证表与旧库没有精确重复，最终得到 10,059 张表。

核心库筛选。删除可由仿射枚举器重新生成的 241 张标量仿射表，再删除可由 Fin4/CDCL 搜索重新生成的 6,283 张阶数不超过 4 的表，剩下 3,535 张阶数大于 4 的候选表。后续交付的 102 张表中有 1 张为 4 阶，因此其中 101 张保留在该候选池。只有通过独立穷举检查的显式表才会保留。

目标 false 空间约包含 3.24 亿个有向问题对。Fin4 独立覆盖约 4,000 万个，剩余约 2.84 亿个。在该剩余集合上重算 3,535 张候选表的覆盖后，删除 2,065 张零边际表，并保留 1,470 张能够在 Fin4 之外增加覆盖的表。

finite149 增补。后续离线审计从一次 order-4 全量实验未生成提交的 789 个方向出发，其中恰好 149 个同时具有官方 false 标签，并且官方 finite outcome 以 proof_false 结尾。ETP 有限蕴含图为 149 个方向全部定位到已证明的有限模型路径，再从相应 Lean 有限反驳源码中抽取表。证明图只负责定位候选；每张入选表随后都在原始任务上直接检查源方程恒真，并找到目标方程的具体失败赋值。

149 个方向压缩为 17 张精确官方基表。其中 11 张还需要相反运算方向，因此任务所需资产共有 28 张有向表，即 17 张原表和 11 张严格转置表。149 个方向中，129 个使用原表，20 个使用转置表。这些资产均未出现在旧 1,470 表库中。

载荷的精确集成。追加的 17 条记录由 16 张与官方表逐字节一致的表，以及 1 张经验证的实现替代表组成。对于 Refutation934，本次提交载荷使用一张 22 阶闭子结构代替 24 阶官方原表，因为历史上的平铺 Lean 证书超过验证时间限制。该 22 阶表已通过穷举检查并覆盖相同的 5 个有向任务。因此，载荷新增 17 条嵌入记录，但没有嵌入 24 阶 Refutation934 原表。

验证与证明边界。解码时检查阶数、记录长度和表项范围，并按行优先完整内容精确去重；同构但字节不同的表不会合并。覆盖数据、证明图路径和排名只用于发现与筛选，不作为证明。运行时只有在 solver 重新穷举确认实际源方程恒真并找到目标方程的具体反例赋值后，表才会被使用；生成的证书还必须通过官方 Lean 评判器。
